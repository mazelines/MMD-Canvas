# MMD Canvas v0.5.9

Harden shader stack restore so it cannot abort workspace opening.

**Requires Windows 11 x64 and a DirectX 12 Ultimate GPU (feature level 12_2, DXR 1.1+).**

## Changes

- Store the shader stack state in the main process **before** attempting the renderer load, and make the load best-effort. Opening a workspace whose shader stack cannot yet load (DX12 renderer not started, or a compile error) no longer aborts the workspace restore.
- Apply the stored stack when the DX12 renderer starts, so a stack restored before the renderer was ready still takes effect.
- Guard the workspace-restore shader apply so a compile error in a saved stack does not prevent the workspace from opening.
- Fixes the v0.5.8 regression where the bundled first-launch example reported the workspace-name tooltip instead of the canvas path (the workspace path was left unset because the shader apply aborted the open).

## Validation and limitations

Local validation uses an RTX 4090. All 40 core tests and the shader-stack editor window UI test passed. The packaged first-launch check now reports the bundled canvas path with DX12 DLAA converging (frame 32) and no error. Packaging verified the runtime files and all 56 Example files.

This is a stability fix on top of v0.5.8; the separate editor window, syntax, and limitations are unchanged. [Implementation and limitations](https://github.com/mazelines/MMD-Canvas/blob/v0.5.9/docs/shader-stack.md).

The installer includes all 56 Example files and opens the bundled canvas on first launch. The installer is unsigned; `SHA256SUMS.txt` contains its checksum. In-app automatic updates are not available.

## 한국어

- 셰이더 스택 상태를 렌더러 로드 전에 메인 프로세스에 먼저 저장하고, 로드는 best-effort로 처리합니다. DX12 렌더러가 아직 시작되지 않았거나 컴파일 오류가 있어도 워크스페이스 복원이 중단되지 않습니다.
- 렌더러 시작 시 저장된 스택을 적용해, 준비 전에 복원된 스택도 반영됩니다.
- 저장된 스택의 컴파일 오류가 워크스페이스 열기를 막지 않도록 보호합니다.
- v0.5.8에서 번들 예제 첫 실행이 캔버스 경로 대신 워크스페이스 이름 툴팁을 보고하던 회귀를 수정했습니다.
- 안정화 수정이며 별도 편집 창·문법·제한은 v0.5.8과 동일합니다.
