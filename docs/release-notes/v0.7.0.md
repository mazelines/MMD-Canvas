# MMD Canvas v0.7.0

Redesign the shader system as a Unity-style per-material model: assign a different shader to each material, with independent property values per material instance.

**Requires Windows 11 x64 and a DirectX 12 Ultimate GPU (feature level 12_2, DXR 1.1+).**

## Changes

- **Per-material shaders**: each PMX material is assigned a shader stack, like a Unity material. The global viewport Lambert/Toon shading modes are **removed**; shading is decided by per-material stack assignment.
- **Built-in stacks**: **Default Toon** (id 1, outline enabled) reproduces the MMD standard toon look as a stack layer (`shadowFloor` 2-band hard step + flat fill); **Standard** (id 2, no outline) is the neutral Lambert base. New materials default to Default Toon. Both are editable and users can add stacks.
- **Independent instance values**: materials sharing a stack still keep their own property values. A shared per-stack DXIL reads `userParams[materialId*STRIDE + localSlot]` at runtime, where `STRIDE` is the library's max property-slot count (baked at compile time). No offset buffer is needed. The `userParams` buffer grows to 4096 float4 slots (65536 bytes).
- **Per-material PSO + outline**: the native renderer selects each material's color PSO from `stackPsos`/`materialStackIds`, and gates the outline hull pass per material via the stack's `outline` flag (`stackOutline`). Outline width/color remain global renderer settings (now always visible, no longer gated on a Toon mode).
- **Renderer-side packing**: `nativeModel` carries the panel→native material id map, so `packMaterialParams` packs each material's instance values into its `materialId*STRIDE` region; value edits re-pack without re-exporting the model.
- **Editor UI**: a material selector picks the editing target; the library panel manages stacks (add/delete/rename, outline ◉ toggle) and assigns them; the property panel edits the **selected material's instance values** (changing one material does not affect others); the center sphere preview shows the selected material's shader.
- **Base shading**: the Toon branch is removed from `baseShading` (always neutral Lambert); `ShadingContext` gains `ambientLux` and `materialId` so Default Toon can reproduce the toon math from context fields.
- **Persistence**: `.canvas` (version 2) stores `shaderLibrary` (with outline flag), `materialInstances` (`stackId` + per-material `params`), and global `outline`. Legacy `shaderStack`/`materialAssign`/render-mode workspaces migrate to the library + instances model.

## Validation and limitations

Local validation uses an RTX 4090. All 41 core tests, the DX12/DLSS/sharpening/presentation/lifetime GPU regressions, and the shader-stack backend test passed (runtime compile → hot-swap → pixel change → property modulation → DepthRimLight → bit-identical restore → compile-error survival). A real-DOM UI test verifies built-in seeding, per-material assignment, the material selector and library list, that an assigned stack changes the material's pixels, that a **per-material instance value change (red→green) alters rendering**, that the preview renders the selected material, and that instance values persist. Packaging verified 528 runtime files and all 56 Example files.

`materialCount*STRIDE ≤ 4096` bounds the parameter buffer; exceeding it requires a limit notice. Changing the library's max slot count changes `STRIDE` and recompiles every stack (async with status). This is a breaking UX change: the global Lambert/Toon mode buttons and the Toon-gated outline panel are gone, replaced by per-material assignment and always-visible outline settings. This remains a native DX12 path only; Three.js `ShaderMaterial` is unsupported. GPUs other than RTX 4090 have not been locally validated. [Implementation and limitations](https://github.com/mazelines/MMD-Canvas/blob/v0.7.0/docs/shader-stack.md).

The installer includes all 56 Example files and opens the bundled canvas on first launch. The installer is unsigned; `SHA256SUMS.txt` contains its checksum. In-app automatic updates are not available.

## 한국어

- 유니티처럼 각 머티리얼에 서로 다른 셰이더(스택)를 지정하고, 같은 스택을 공유해도 프로퍼티 값은 머티리얼마다 독립적으로 갖도록 재설계했습니다. 뷰포트 전역 Lambert/Toon 모드는 제거했습니다.
- 빌트인 스택 Default Toon(아웃라인 포함, MMD 표준 툰 look 재현)과 Standard(중립 Lambert)를 제공하며, 새 머티리얼에는 Default Toon이 기본 할당됩니다.
- 스택별 공유 DXIL에 `userParams[materialId*STRIDE + localSlot]` 런타임 인덱싱으로 머티리얼 인스턴스를 분리합니다(오프셋 버퍼 불필요). userParams 버퍼는 4096슬롯(65536바이트)으로 확장했습니다.
- 네이티브가 머티리얼별 color PSO를 선택하고, 스택의 outline 플래그로 아웃라인 헐 패스를 머티리얼마다 게이트합니다. 아웃라인 두께/색상은 전역 설정이며 항상 표시됩니다.
- 렌더러가 panel→native 머티리얼 매핑으로 인스턴스 값을 패킹하며, 값 변경 시 모델 재익스포트 없이 재패킹만 합니다.
- 편집기에 머티리얼 선택기·라이브러리 관리(아웃라인 ◉)·할당·머티리얼별 프로퍼티 편집·선택 머티리얼 프리뷰를 추가했습니다.
- 베이스의 Toon 분기를 제거하고 ShadingContext에 ambientLux·materialId를 추가했습니다. `.canvas`는 shaderLibrary·materialInstances·전역 outline을 저장하며 레거시 워크스페이스를 마이그레이션합니다.
- `materialCount*STRIDE ≤ 4096` 제한이 있으며, 라이브러리 최대 슬롯 수 변경 시 전체 재컴파일합니다. 전역 모드 버튼 제거는 파괴적 UX 변경입니다. 네이티브 DX12 전용 경로이며 Three.js ShaderMaterial은 지원하지 않습니다.
