# MMD Canvas v0.5.8

Move the shader stack editor into a dedicated editor window opened from the View menu.

**Requires Windows 11 x64 and a DirectX 12 Ultimate GPU (feature level 12_2, DXR 1.1+).** DLAA and DLSS availability still depends on the NVIDIA RTX GPU and driver; unsupported GPUs use DX12 MSAA 4×.

## Changes

- Replace the inspector "Shader Stack" tab with a **separate editor window**, opened from **View → Shader Stack Editor…** (Ctrl+Shift+K). The window is a singleton: closing it keeps the stack state in the main process, and reopening restores it.
- The editor window is edit-only (stack, code, auto-generated properties); it has no preview canvas. Applying a stack re-renders the **main viewport**.
- The main process now owns the stack state as the single source of truth. The editor queries/updates it over IPC (`shader-stack:get/apply/params`); the main process compiles, hot-swaps the native color PSOs, uploads parameters, and notifies the main viewport to re-render. Workspace save/restore serializes through this state.
- Serialize native-channel requests (renders and shader loads) with a host mutex so a shader hot-swap never collides with an in-flight frame, without pausing the render flush.
- Reset temporal history on a shader hot-swap so DLAA converges to the new shading instead of blending it against stale frames. Fix a flush-exit race that could leave a requested re-render stalled.
- Older workspaces that reference the removed inspector tab fall back to the overview tab on restore.

## Validation and limitations

Local validation uses an RTX 4090. All 40 core tests, the DX12/DLSS/sharpening GPU regressions, the presentation-recovery and 1,200-frame lifetime tests, and the shader-stack backend test (runtime compile → hot-swap → pixel change → bit-identical restore → compiler-error survival) passed. A real-DOM UI test opens the window from the menu, adds a layer (CodeMirror + auto-generated properties), applies it so the main viewport changes, resets to baseline, and round-trips the stack through workspace persistence. Local packaging verified 528 runtime files and all 56 Example files.

The editor window has no live preview by design; the result is shown in the main viewport. Runtime compilation can take a few seconds and runs asynchronously. A user shader that hangs the GPU is bounded by the existing 10-second fence timeout. This remains a native DX12 path only; Three.js `ShaderMaterial` is unsupported. GPUs other than RTX 4090 have not been locally validated. [Implementation, syntax and limitations](https://github.com/mazelines/MMD-Canvas/blob/v0.5.8/docs/shader-stack.md).

The installer includes all 56 Example files and opens the bundled canvas on first launch. The installer is unsigned; `SHA256SUMS.txt` contains its checksum. In-app automatic updates are not available.

## 한국어

- 셰이더 스택 편집기를 인스펙터 탭에서 **별도의 편집 전용 창**으로 분리했습니다. **보기 메뉴 → 셰이더 스택 편집기…**(Ctrl+Shift+K)로 엽니다. 창을 닫아도 스택 상태는 메인 프로세스에 유지되어 다시 열 때 복원됩니다.
- 창은 편집 전용(스택·코드·자동 프로퍼티)이며 미리보기가 없습니다. 적용 결과는 메인 뷰포트에 반영됩니다.
- 스택 상태는 메인 프로세스가 단일 출처로 관리하고, IPC로 조회·갱신합니다. 워크스페이스 저장·복원도 이 상태를 직렬화합니다.
- 렌더 채널을 호스트 mutex로 직렬화해 셰이더 로드가 진행 중인 렌더와 충돌하지 않습니다. 셰이더 핫스왑 시 시간 이력을 리셋해 DLAA가 새 셰이딩으로 수렴하며, flush 종료 레이스를 수정했습니다.
- 제거된 인스펙터 탭을 참조하는 이전 워크스페이스는 복원 시 개요 탭으로 대체됩니다.
- 런타임 컴파일은 수 초 걸릴 수 있으며 비동기로 처리합니다. GPU를 멈추는 셰이더는 기존 10초 펜스 타임아웃으로 제한됩니다. 네이티브 DX12 전용 경로이며 Three.js ShaderMaterial은 지원하지 않습니다.
